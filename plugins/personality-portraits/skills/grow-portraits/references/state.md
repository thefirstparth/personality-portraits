# Persistent state and review contract

Keep existing queues intact. Use `queue/candidates.json` for canonical candidate records and `queue/runs/YYYY-MM-DD.json` for daily run state. If those files are missing with a definite 404, initialise them; network/authentication errors do not mean absence. Migrate older dated queues additively by canonical identity, preserving evidence and blocked/review states. Never generate while durable request counters cannot be saved.

Candidate document: `schema_version: 1`, `people: {id: record}`. Each record contains id, name, aliases, categories, origin (`direct` or `expansion`), first_seen_at, last_seen_at, status, evidence, expansion_links and identity_confidence. Evidence entries contain site URL, section, excerpt, edition_date, observed_at and content_hash. Expansion links contain seed_id, category, reason, ranking_date, ranking_sources. Promote an expansion record to direct if a source-site mention later arrives; keep its history. Statuses: queued, researching, draft, awaiting_review, approved, published, deferred, blocked. Existing approved metadata is authoritative for publication availability.

Daily run document: `schema_version:1`, `date`, `timezone:"Asia/Kolkata"`, `base_sha`, `run_id`, `lease_expires_at`, `selected_ids:[]`, `attempts:{id:count}`, `accepted_ids:[]`, `published_ids:[]`, `expansions:{category:{seed_id,nominee_ids,observed_at}}`, `source_reads:[]`, `events:[]`. Record IDs as unique lists. accepted_ids means an actual approved deliverable, not successful generation. Include replacements in the six/day ceiling. Sum attempts <=12; each person's count <=2. An uncertain provider request counts. Reserve attempt counters before calling generation. Daily retry requests reuse this same ledger. Historical ledgers are immutable except evidence-backed reconciliation of publication outcomes.

Claim production with an atomic GitHub commit of a unique run_id and a 30-minute lease based on current head. Renew before expiry. Respect an unexpired lease owned by another run and return its status. An expired lease may be reclaimed after checking current remote commits and draft evidence. Before generation and publication verify current ownership. Non-force updates prevent competing claims based on the same head; after a conflict reread and reconcile, never generate first. Commit request reservations sequentially; parallel image calls are allowed only after all requests are durably reserved under the same lease. Release lease on completion or report an interrupted run for expiry recovery.

Count requests on the IST date they are reserved, and individual acceptances on the IST date of actual owner approval. Count publication on its actual IST date. On every date, the union of accepted_ids and published_ids contains at most six distinct person IDs; publishing a portrait approved that same day does not count it twice. Approved backlog from earlier days consumes today's publication slots. Count all image-provider generation and edit-repair requests as attempts. Do not reset dates/counters when a run crosses midnight; finish bookkeeping under its real event date, acquire the new day's lease and reconcile limits before further requests or publication.

Selection rule: six accepted-or-published maximum, four direct plus two related normally. Borrow empty allocations from qualified backlog. A run can select fewer than six. Further candidates can replace a failed selection only within the twelve-attempt cap and six-portrait cap; never lose earlier attempt counters. Respect one expansion batch per category per day and seven days per seed. Check prior ledgers for cooldown before nominating. Do not generate expansion nominations recursively. During another run's live lease, read-only discovery is permitted but shared queue/state writes, request reservations, generation and publication are not.

Review/publication gate: preserve `publication_enabled=false` until the owner explicitly authorises publishing the reviewed first batch. `style_approved=true` records the general design-language approval, not individual image approval. Later publication still requires genuine approved_by/approval_reference fields as demanded by the repository validator. If the owner explicitly changes the ongoing review policy, update the validator and metadata contract transparently in a separate authorised change; don't invent human approval.

Reference photos, unapproved drafts and personal/private information stay out of the public repository. Store reproducible prompts, public discovery evidence, candidate decisions and non-sensitive run state there. Retain host-saved drafts privately. A public candidate record is not an image API response. Do not add an artwork reuse license on the owner's behalf without their selection.
